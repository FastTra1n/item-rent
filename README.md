## Назначение

Консольное приложение для аренды бытовых вещей, электроники и инструментов. Проект позволяет пользователю найти нужную вещь и забронировать её на определённый срок, не покупая её.

## Основной функционал

- Отображение полного списка вещей, доступных для бронирования
- Добавление новой вещи для аренды
- Поиск конкретной вещи по указанному названию
- Проверка доступности конкретной вещи для бронирования
- Бронирование конкретной вещи на указанные даты
- Отмена существующей брони
- Отображение списка всех пользователей системы
- Добавить нового пользователя в систему
- Нахождение конкретного пользователя по его уникальному идентификатору

## Используемые технологии

## Целевая аудитория

1. **Арендаторы**: люди, которым необходимы инструменты, различного рода техника или спортивный инвентарь "здесь и сейчас".
2. **Владельцы**: владельцы вещей, которые хотят получать доход от сдачи предметов в аренду.

## Предметная область

Основными объектами предметной области являются:

- Вещь;
- Бронирование;
- Пользователь.

Приложение относится к сфере аренды и шеринг-экономики. Приложение позволяет удобно искать товары, проверять доступность конкретных предметов на выбранные даты, бронировать вещи, расчитывать стоимость, а также установливать статус бронирования.

## Основные сущности

### Item – вещь

Объект `Item` представляет вещь, доступную для аренды.
Основные атрибуты:

- `id` – уникальный идентификатор вещи;
- `owner` – владелец вещи (объект `User`);
- `name` – название вещи;
- `price` – цена аренды вещи;
- `deposit` – залоговая стоимость вещи;
- ``
  Основные методы:
- `__str__()` – строковое представление вещи.

### User – клиент

Объект `User` представляет пользователя системы.
Основные атрибуты:

- `id` – уникальный идентификатор;
- `name` – имя пользователя;
- `phone` – контактный номер.
- `rating` – рейтинг пользователя.
  Основные методы:
- `from_data()` – создание объекта `User` из набора данных;
- `__str__()` – строковое представление пользователя.

### Booking – аренда

Объект `Booking` связывает вещь (`Item`) и клиента (`User`).
Основные атрибуты:

- `id` – уникальный идентификатор аренды;
- `item` – арендуемая вещь (объект `Item`);
- `user` – пользователь-арендатор (объект `User`);
- `start_date`, `end_date` – период аренды;
- `is_cancelled` – признак отмены аренды.
  Основные методы:
- `cancel()` – отмена аренды;
- `__str__()` – строковое представление аренды.

## Страницы веб-интерфейса

- `/` - главная страница: описание приложения и навигация (view-функция `index()`);
- `/items/` - каталог вещей: объекты `Item` из `data/items.json` (view-функция `items_list()`);
- `/items/<int:item_id>/` - страница конкретной вещи (view-функция `item_detail()`);
- `/bookings/` - список бронирований: объекты `Booking` из `data/bookings.json` (view-функция `bookings_list()`);
- `/bookings/<int:booking_id>/` - страница бронирования (view-функция `booking_detail()`).

## Основные операции

### Работа с вещами

- Добавление новой вещи в базу;
- Поиск существующей вещи по названию;
- Отображение полного списка вещей из базы.

### Работа с пользователями

- Добавление нового пользователя в базу;
- Поиск пользователя по его уникальному ID;
- Отображение полного списка пользователей системы.

### Работа с бронированиями

- Проверка возможности бронирования вещи на указанный период;
- Создание нового бронирования;
- Отмена существующего бронирования;
- Получить текущий статус бронирования.

## Хранение данных

Данные приложения хранятся в отдельных JSON-файлах:

- `data/items.json` - вещи, доступные для бронирования;
- `data/bookings.json` - список бронирований;
- `data/users.json` - пользователи системы.

При загрузке данные из JSON преобразуются в соответствующие им объекты `Item`, `Booking` и `User`.

## Веб-интерфейс

Веб-часть приложения реализована на Django.
Основные страницы:

- главная страница;
- список вещей доступных для аренды;
- информация о каждой из вещей;
- список бронирований;
- информация об отдельном бронировании.

Для формирования страниц используются Django-шаблоны.
Генерация HTML непосредственно в Python-коде веб-представлений не используется. Представления подготавливают данные и передают их в шаблоны через контекст.

## Django Template Language

Шаблоны используют возможности Django Template Language.

### Базовый шаблон

Общий шаблон страниц:
templates/base.html
Он содержит общую HTML-структуру страницы, подключение стилей и JavaScript, навигацию и блоки для содержимого отдельных страниц.
Дочерние шаблоны используют наследование:

```django
{% extends "base.html" %}
```

Содержимое отдельных страниц размещается в блоке:

```django
{% block content %}
  ...
{% endblock %}
```

Заголовок страницы задаётся через блок:

```django
{% block title %} ... {% endblock %}
```

### Включаемые шаблоны

Повторяющиеся фрагменты вынесены в отдельные шаблоны.
Для вещей используется:
`items/includes/item_card.html`
Для отображения состояния бронирования:
`bookings/includes/booking_status.html`
Подключение выполняется с помощью команд:

```django
{% include "items/includes/item_card.html" %}
```

или:

```django
{% include "bookings/includes/booking_status.html" %}
```

### Контекст

Представления передают данные в шаблоны через словарь контекста.
Например, для списка помещений:

```py
context = {
    "items": items_list,
}
```

В шаблоне данные доступны по имени переменной:

```django
{% for item in items %}
```

Для страницы отдельного помещения используется переменная:

```django
{{ item }}
```

Аналогичный подход используется для бронирований.

### Циклы и условия

Для формирования списков используются циклы:

```django
{% for item in items %}
```

При отсутствии элементов используется:

```django
{% empty %}
```

Условия используются для отображения различного содержимого страницы и состояния бронирования:

```django
{% if booking.is_cancelled %}
```

## Фильтры шаблонов

В шаблонах используются стандартные фильтры Django Template Language.
Например, количество помещений:

```django
{{ items|length }}
```

Для отображения значения по умолчанию:

```django
{{ item.name|default:"Без названия" }}
```

Фильтры используются для представления данных и не содержат бизнес-логику приложения.

## 8. URL-маршрутизация

Для страниц используются именованные маршруты Django.
Примеры:

```django
{% url 'items:list' %}
{% url 'items:detail' item.id %}
{% url 'bookings:bookings' %}
{% url 'bookings:detail' booking.id %}
```

Для приложений используются пространства имён (`namespace`), что позволяет обращаться к маршрутам через имена вида:

`items:list`

`items:detail`

`bookings:bookings`

`bookings:detail`

Ссылки в шаблонах формируются через `{% url %}`, а не за счёт жёстко заданных адресов.

## 9. Статические файлы

Статические файлы проекта находятся в каталоге:
`homepage/static/homepage/`
Используются: `css/style.css`, `js/main.js`, `img/logo.png`

Для работы со статическими файлами в шаблонах используется:

```django
{% load static %}
```

CSS подключается через:

```django
{% static 'homepage/css/style.css' %}
```

Изображение:

```django
{% static 'homepage/img/logo.png' %}
```

JavaScript:

```django
{% static 'homepage/js/main.js' %}
```

В проекте используется собственный CSS для оформления элементов интерфейса. JavaScript используется для небольшого динамического поведения интерфейса, в том числе для автоматического отображения текущего года в нижней части страницы.

## Назначение модулей

### `main.py`

Основная точка входа в приложение, отвечающая за запуск приложения, отображение меню с выбором доступных опций и вызов методов с логикой из основных модулей.

### `rently/`

Пакет настроек Django-проекта:

- `settings.py` - настройки проекта;
- `urls.py` - маршрутизация верхнего уровня;
- `asgi.py`, `wsgi.py` - точки взаимодействия с сервером.

### `homepage/`

Django-приложение главной страницы:

- `views.py` – обрабатывает веб-запросы, связанные с домашней страницей;
- `urls.py` – маршрут главной страницы.

### `items/`

Django-приложение каталога вещей:

- `views.py` – обрабатывает веб-запросы, связанные с каталогом вещей;
- `urls.py` – маршруты приложения;

### `bookings/`

Django-приложение системы бронирования:

- `views.py` – обрабатывает веб-запросы, связанные с бронированиями;
- `urls.py` – маршруты приложения;

### `models/`

Классы предметной области и функции работы с ними:

- `items.py` – класс `Item` и функции работы с вещами;
- `users.py` – класс `User` и функции работы с пользователями;
- `bookings.py` – класс `Booking` и функции работы с бронированиями.

### `storage.py`

Отвечает за подгрузку/сохранение информации о вещах, бронированиях и пользователях в системы.

### `utils.py`

Содержит в себе вспомогательные функции:

- `input_int()` - безопасный ввод целого числа;
- `input_date()` - безопасный ввод даты.

### `tests.py`

Содержит автоматизированные тесты для проверки корректности выполняемой логики.
